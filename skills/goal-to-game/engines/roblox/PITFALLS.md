# Roblox pitfalls

## Container ID is not a MeshPart ID

An Open Cloud upload can identify a Model/package while the game needs descendant MeshPart IDs.
Never paste the container ID into every MeshPart. Verify descendants after Studio import.

## Evidence JSON can lie

A schema that accepts `movingPartVerified: true` or an arbitrary `https://` URL is not verification.
Require files generated by Studio, hash them, and validate that referenced files exist.

## Rojo can erase imported state

Do not map `Workspace/ThrixelAssets` from disk. Imported MeshIds belong to the Studio place state.

## Grouping can destroy motion

If a wheel, door, beacon, propeller, or turret is missing from `keep_groups`, it becomes static body
geometry. Inspect node names first; never guess.

## Geometric center is not always a hinge

A kept group can still have the wrong pivot. Put an attachment/pivot at the mechanical axis and
rotate the parent.

## Material slots need addressability

Roblox does not provide Unity-style arbitrary submesh material assignment on one MeshPart. Preserve
separate objects where material regions need different `SurfaceAppearance` data.

## Moderation is not a broken reference

A correct asset may not render while Roblox moderation is pending. Record the state and avoid
re-upload loops.

## "Mobile test" is easy to overclaim

A Studio viewport resized to a mobile resolution is useful, but it is not a physical-device benchmark.
Label it `mobile-sized Studio viewport` unless a real device was used.

## Screenshot automation needs permission

Studio capture APIs are permissioned for plugins. A denied permission is a hard evidence gap, not a
reason to substitute fabricated images.

## Local collector should stay local

Bind the collector to `127.0.0.1`, use a random session token, cap payload sizes, sanitize filenames,
and never expose it on the LAN or internet.
